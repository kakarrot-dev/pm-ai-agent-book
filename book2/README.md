# AI Agent 产品经理实战：进阶篇

[开始阅读](00-introduction.md) · [返回项目首页](../README.md) · [查看入门篇](../book1/README.md)

## 书稿定位

这是一本面向 AI 产品经理的 Agent 产品工程教材。它不教读者围绕某个框架搭建项目，而是帮助读者理解：产品要求怎样落实到上下文、知识、记忆、工具、执行路径、用户控制、评估和生产系统中。

进阶篇按照 Agent 从理解目标到进入生产的工程链路组织。入门篇回答“一个 Agent 产品值不值得做、应该做成什么”，进阶篇继续回答“怎样把这个产品稳定地做出来，并证明它可以发布和持续运营”。

## 目标读者

本书适合三类读者：

- 已经读过入门篇，希望继续理解 Agent 产品工程；
- 正在设计或交付 Agent 产品，需要与算法和工程团队共同做决策；
- 已有 AI 产品经验，希望系统补齐可靠性、安全、评估和生产化方法。

默认读者理解基本的 Agent 产品概念，但不要求独立实现框架、训练模型或搭建完整生产系统。

## 非目标

- 不写成某个 Agent 框架的 API 教程。
- 不提供需要从零搭建环境的完整工程脚手架。
- 不用组件数量或架构复杂度代表产品成熟度。
- 不把模型输出、系统状态和外部世界事实混为一谈。
- 不用脱离具体任务的技术术语代替产品判断。

## 全书结构

### 第一篇：设计模型每一步依据什么判断

1. [Prompt 与 Context Engineering](01-prompt-and-context-engineering.md)：定义模型每一步应该看到什么，以及信息怎样写入、选择、压缩和隔离。
2. [Retrieval / Knowledge Engineering](02-retrieval-and-knowledge-engineering.md)：让 Agent 取得当前、可信、可引用且符合权限的外部知识。
3. [Memory Engineering](03-memory-engineering.md)：决定哪些信息应该跨步骤或跨会话保留，以及怎样更新和遗忘。

### 第二篇：把行动过程变成可控机制

4. [Tool Loop Engineering](04-tool-loop-engineering.md)：设计 Agent 怎样行动、观察、继续、停止和恢复。
5. [Graph Engineering](05-graph-engineering.md)：把状态、执行单元、路径、人工介入和 Checkpoint 变成可执行机制。
6. [Agent Experience Engineering](06-agent-experience-engineering.md)：让用户能够委托任务、理解进度、确认风险并随时接管。

### 第三篇：建立发布证据与故障边界

7. [Harness + Eval Engineering](07-harness-and-eval-engineering.md)：稳定运行评估，比较候选版本并形成发布证据。
8. [Reliability Engineering](08-reliability-engineering.md)：让 Agent 在超时、重试、依赖波动和进程中断后仍然保持正确。
9. [Safety Engineering](09-safety-engineering.md)：限制越权、伤害和其他不可接受的行动。

### 第四篇：进入生产并持续经营

10. [Production Engineering](10-production-engineering.md)：把版本、发布、观测、成本、支持和运营接成生产闭环。

[引言](00-introduction.md)解释为什么产品经理需要理解这些工程问题，[后记](11-afterword.md)讨论怎样避免把 Engineering 变成新的术语清单。

## 专题之间的关系

这些专题不是相互独立的技术栈。一次生产故障可能同时涉及错误检索、过期记忆、工具副作用、恢复状态和用户误解。

阅读时始终保留三个坐标：

- **目标**：用户最终要完成什么？
- **依据**：系统根据哪些可信信息决定下一步？
- **证据**：团队怎样证明结果、过程、风险和成本可以接受？

## 进阶篇新增什么

入门篇已经解释了目标、授权、控制、评估和风险等产品要求。进阶篇不再重复证明这些要求为什么重要，而是继续追问它们怎样落入系统：

| 入门篇提出的要求 | 进阶篇继续解决的问题 |
| --- | --- |
| Agent 应该理解用户目标 | 当前一步怎样组装 Prompt、Context 和可信知识 |
| 产品需要保存任务状态 | State、Memory 和 Checkpoint 分别保存什么 |
| 工具调用必须受控 | 参数、权限、副作用、Observation 和停止条件怎样进入 Tool Loop |
| 用户应该能够暂停和接管 | 运行时状态怎样真正响应修改、暂停、取消和接管 |
| 发布需要评估证据 | Dataset、Target、Trace、Evaluator 和门禁怎样组成 Harness |
| 失败后应该恢复 | 步骤身份、幂等、结果核验和故障注入怎样防止重复副作用 |

读者不需要为了理解产品决策而掌握某个框架 API。代码和协议示例只用于说明责任边界及验收方式。

## 每章的基本组成

每章原则上包含：

1. 一个具体的产品或工程问题；
2. 核心机制及其责任边界；
3. 可以落入 PRD、Brief 或数据契约的设计方法；
4. 结果、轨迹、风险和成本的验证方式；
5. 常见失败方式与适用边界；
6. 本章小结与思考题；有直接帮助的资料再补充延伸阅读或参考资料。

各专题复杂度不同，不要求机械使用相同的小标题。正文优先解释产品经理需要做出的判断，再补充必要的协议、状态和代码示意。

## 图示与代码块约定

- 概念插画用于建立章节的整体心智模型，图中尽量不承载长段文字。
- 流程图用于解释上下文组装、检索、Tool Loop、评估和生产闭环。
- 状态图用于解释任务等待、恢复、失败和结束状态。
- 架构图用于解释 State、Node、Edge、Checkpoint、工具和外部系统的关系。
- Mermaid 图保留可编辑的结构表达，正文插画负责帮助读者快速理解。
- 代码块只展示 Prompt、协议、状态、数据结构、伪代码和最小实现，不提供完整工程脚手架。

## 建议阅读方式

第一次阅读建议按章节顺序进行。第 1 至 3 章建立模型决策所依赖的信息基础，第 4 至 6 章解释 Agent 怎样行动以及用户怎样控制，第 7 至 9 章建立评估、可靠性和安全边界，第 10 章把这些能力接入生产运营。

如果正在解决具体问题，也可以按场景查阅：

- 知识问答或企业搜索：第 1 至 3 章；
- 工具调用、长任务或流程自动化：第 4、5、8 章；
- 授权、进度、确认和人工接管：第 6、9 章；
- 灰度、发布和规模化运营：第 7 至 10 章。

第 1、3、4、5、7 章篇幅较长，可以先阅读章首问题、核心图示和本章小结，再按当前项目需要进入 PRD、代码或评估示例。

## 学完以后

读完进阶篇，读者应该能够与算法和工程团队共同完成以下工作：

- 定义模型每一步需要的 Context、知识和记忆；
- 把工具、状态、路径、人工介入和恢复写成可验收协议；
- 设计能够比较版本、解释失败并阻断严重风险的 Eval Harness；
- 用可靠性、安全、成本和运营证据决定发布、灰度、降级或回滚。
