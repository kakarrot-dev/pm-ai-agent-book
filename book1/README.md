# AI Agent 产品经理实战：入门篇

[开始阅读](00-introduction.md) · [返回项目首页](../README.md) · [进入进阶篇](../book2/00-introduction.md)

## 书稿定位

这是一本面向 AI 产品经理的 Agent 产品教材。它不教读者从头实现一个 Agent，而是帮助读者回答一组更接近产品工作的关键问题：什么需求值得 Agent 化，应该给 Agent 多大自主权，怎样设计用户控制权，如何选择能力方案，又该怎样评估、上线和持续运营。

全书按照产品生命周期组织，从机会识别一路推进到规模化经营。技术内容不会消失，但只在它能够帮助产品经理做出选择时出现。

## 目标读者

本书适合两类读者：

- 已有传统产品经验，希望转型为 AI 产品经理；
- 已经在做 AI 产品，希望系统补齐 Agent 产品方法论。

默认读者理解基本的产品工作流程，但不要求具备编程、模型训练或 Agent 工程经验。

## 非目标

- 不写成 Agent 编程或模型训练教程。
- 不从零讲授通用用户研究、PRD 和项目管理基础。
- 不覆盖传统推荐、预测、风控等非生成式 AI 产品。
- 不用热门技术名词代替真实的用户问题和产品判断。

## 两条贯穿全书的案例

### 客户服务与事务办理 Agent

这条案例线处理退款、投诉、取消订阅等事务。它代表一类需要替用户进入外部系统、与其他参与者沟通并对结果负责的 Agent 产品。案例重点是外部执行、长流程、金钱风险、用户授权和结果闭环。

### 企业知识与办公 Agent

这条案例线处理内部知识查询、材料生成、跨系统操作和审批协作。它代表一类嵌入组织信息与工作流程的 Agent 产品。案例重点是可信知识、权限隔离、信息时效、组织协作和效率。

每章先讲一套共同方法，再分别展示两类产品如何应用，最后比较它们在目标、权限、风险、体验和指标上的差异。

## 每章的基本组成

每章原则上包含：

1. 本章需要解决的产品问题；
2. 一个具体的决策场景；
3. 核心概念与判断框架；
4. 两条主案例的应用；
5. 两类产品的决策差异；
6. 常见失败方式；
7. 产品经理可使用的检查表或交付模板；
8. 本章小结与思考题。

这套结构用于保证全书一致性，不要求每章机械使用相同的小标题。正文优先保持自然、连续的阅读体验。

## 图示与代码块约定

- 概念插画用于建立章节的整体心智模型，图中尽量不承载长段文字。
- 流程图用于解释任务执行、授权、人工接管、异常恢复和评估闭环。
- 架构图用于解释模型、上下文、记忆、知识、工具和业务系统的关系。
- 状态图用于解释任务从创建、执行、等待到完成或失败的变化。
- Mermaid 图保留可编辑的结构表达，正文插画负责帮助读者快速理解。
- 代码块只用于 Prompt、结构化输入输出、简化配置、伪代码和产品协议示例。
- 不加入要求读者搭建环境的完整工程代码。

## 建议阅读方式

第一次阅读建议按章节顺序进行。第 1 至 3 章帮助判断“是否值得做”，第 4 至 6 章回答“应该做成什么”，第 7 至 9 章回答“如何证明有效并稳定经营”，第 10 章再讨论能力扩展与组织建设。

如果正在推进具体项目，也可以直接进入对应章节，并使用章末的检查表或模板复核当前决策。

## 学完以后

读完入门篇，读者应该能够完成四类交付：

- 判断一个需求是否值得 Agent 化，并说明硬门槛；
- 写出包含目标、状态、异常、权限和完成证据的任务模型；
- 定义产品边界、自主等级、用户控制和能力方案；
- 用评估、风险、成本和运营证据决定是否发布或扩展。

需要把这些产品要求继续落成 Context、工具、状态、恢复和发布机制时，可以进入[进阶篇](../book2/00-introduction.md)。
